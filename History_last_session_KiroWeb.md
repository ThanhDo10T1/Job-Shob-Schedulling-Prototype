1\. L2S (Learning to Search) — ICLR 2024
----------------------------------------

**Bản chất**: Một **framework** (không phải một model), do Cong Zhang và cộng sự đề xuất, chuyển bài toán JSSP từ **construction heuristic** sang **improvement heuristic**.

### Luận điểm nền tảng

*   Disjunctive graph **không thể encode đầy đủ** partial solution (thiếu thông tin WIP, machine load) → construction heuristic bị bias.
*   Giải pháp: chuyển sang improvement heuristic — mỗi state là một **complete solution** biểu diễn bằng DAG đầy đủ thông tin → bài toán scheduling trở thành **bài toán tìm kiếm trên cấu trúc đồ thị**.

### Bộ khung 5 trụ cột

#

Thành phần

Nội dung

1

Local search loop

Initial solution → graph → policy chọn swap → cập nhật → lặp

2

N₅ neighborhood

Critical block, swap đầu/cuối,

3

Graph embedding

**GIN (TPM) + GAT (CAM)** dual-module

4

MDP

State = complete solution; Action = cặp ops; Reward = step-wise improvement

5

Message-passing evaluator

Tính EST/LST song song trên GPU thay CPM tuần tự (nhanh hơn 11.4×)

### MDP

*   **Node feature**: `(p_ji, est_ji, lst_ji) ∈ ℝ³` — quan sát tinh tế: nếu node nằm trên critical path thì `est = lst`, ngầm encode tín hiệu critical path.
*   **Reward**: `r(s_t, a_t) = max(C_max(s*) − C_max(s_{t+1}), 0)` → cumulative reward = tổng improvement so với solution ban đầu.
*   **Training**: n-step REINFORCE (giải vấn đề sparse reward + OOM khi T lớn).

### Kết quả định vị

L2S là **paper đầu tiên** mà DRL vượt CP-SAT (OR-Tools) trên Taillard 100×20 và instance cực lớn (1000 jobs, 40k operations) với gap −15% đến −24%.

2\. TBGAT (Topology-aware Bidirectional GAT) — ICML 2024
--------------------------------------------------------

**Bản chất**: Cùng nhóm tác giả, **kế thừa nguyên vẹn framework L2S** rồi thay riêng phần representation. Đây là quan hệ **"framework → instantiation tốt hơn"**, không phải hai phương pháp cạnh tranh.

### Phê phán L2S (TBGAT nêu thẳng)

1.  **GIN trong TPM** thiết kế cho đồ thị **vô hướng**, nhưng disjunctive graph (complete solution) là **DAG có hướng** → có thể mất thông tin hướng.
2.  **GAT trong CAM**: trong subgraph G\_J hoặc G\_M, mỗi node thường chỉ có **1 neighbour** → attention vô nghĩa (không có gì để "cân").

### Ba cải tiến mắt xích

**(1) Bidirectional view thay cho dual-module** Thay vì tách theo loại arc (như L2S), TBGAT tách theo **chiều truyền tin**:

*   **FEM (Forward)**: gốc → lá, mang historical context. Feature: `(p_x, est_x, Φ→_x)`
*   **BEM (Backward)**: lá → gốc, mang future schedule. Feature: `(p_x, lst_x, Φ←_x)`
*   Mỗi node giờ có **nhiều neighbour** theo từng chiều → attention thực sự có việc → sửa cả 2 vấn đề trên.

**(2) Topological sort như feature tường minh** (đóng góp lý thuyết cốt lõi)

*   **Lemma 1**: predecessor ⟹ Φ→ và EST nhỏ hơn → forward topo sort ↔ global processing order.
*   **Corollary 1**: đối xứng cho backward sort ↔ LST.
*   Tồn tại **bijection** giữa không gian topo và không gian schedule khả thi → học topo = học phân biệt chất lượng solution.

**(3) MPTS (Message-Passing Topological Sort)**

*   Tổng quát hoá đúng ý tưởng evaluator của L2S sang tính topo sort.
*   **Theorem 1**: áp dụng MPO (max-pooling) đủ lần thì xác định được topo sort, batch trên GPU.
*   **Theorem 2**: complexity tuyến tính O(|J|+|M|), chứng minh "follows L2S proof".

**(4) Entropy-regularized REINFORCE** — chỉ thêm số hạng entropy vào loss để khuyến khích exploration.

*   TBGAT-500 đánh bại L2S-500 ở gần như mọi instance (ví dụ Taillard 100×20: 6.4% vs 7.9%).
*   TBGAT-1000 đạt gap nhỏ hơn L2S-2000 → hiệu quả ~2× về số bước.

*   Tìm được optimal cho FT 6×6, LA 15×5, LA 20×5, LA 30×10 — "while L2S fails to do so".

------------------

*   **L2S định nghĩa luật chơi** (paradigm shift + bộ khung MDP + evaluator).
*   **TBGAT chơi cùng luật đó nhưng với bộ biểu diễn topology có cơ sở lý thuyết vững hơn**, và thắng một cách có kiểm soát — gần như là "ablation study được nâng cấp thành paper riêng".

\# L2S for Job-Shop Scheduling — Colab project

A compact, from-scratch \*\*PyTorch\*\* re-implementation of the \*Learning-to-Search\* (L2S)
improvement heuristic for the Job-Shop Scheduling Problem (JSSP), packaged as a
\*\*Google Colab notebook\*\* you can run cell by cell.

> Reference: Cong Zhang et al., \*Deep Reinforcement Learning Guided Improvement Heuristic
> for Job Shop Scheduling\*, ICLR 2024.

## Files

| File | Purpose |
|------|---------|
| \`L2S\_JSSP\_Colab.ipynb\` | \*\*Main deliverable.\*\* 16 cells: data → graph/CPM → N5 → env → GIN+GAT policy → n-step REINFORCE → train → evaluate → Gantt. Open in Colab and Run-All. |
| \`build\_notebook.py\` | Generator that produces the \`.ipynb\` (edit here, then \`python3 build\_notebook.py\`). |
| \`\_validate\_core.py\` | Pure-Python (no deps) check of the algorithmic core: confirms the message-passing EST evaluator equals CPM, and that N5 local search reduces makespan. |

## How to use

1. Upload \`L2S\_JSSP\_Colab.ipynb\` to \[Google Colab\](https://colab.research.google.com/)
   (or \`File → Open notebook → GitHub\`).
2. (Optional) \`Runtime → Change runtime type → GPU\`.
3. \`Runtime → Run all\`. Training on the default 6×6 setting takes a few minutes.

No \`pip install\` needed — it uses only \`torch\`, \`numpy\`, \`matplotlib\`, all pre-installed on Colab.
